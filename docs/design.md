# 私铁经营模拟游戏 设计文档

Nov 6, 2026 · @すもも

## 概述

玩家经营一家日本式私营铁路公司，在架空的城市里修铁路、开发沿线土地、调度列车，看着城市沿着自己的线路生长。参考的现实原型是关西私铁「先买地、再修路、靠地产和铁路互相养活」的经营模式。

- **定位**：手机优先（竖屏横屏都支持）的 3D 铁路经营与城市发展模拟，Web 技术，可打包为桌面版
- **玩家身份**：私铁公司。铁路、车辆、人员、票价必须真实；城市的样貌由规则自动生长，玩家只在自己的土地上指定用途
- **三层玩法**：线网规划（轨道层面）、沿线开发（买地与分区）、列车调度（分层自动化）互相影响
- **核心卖点**：规划决定调度难度（修单线省钱但跑不快）；铁路通到哪里，那里的街景就变新变高
- **参考作品**：A列車で行こう（铁路+地产）、TheoTown（斜俯视城市画面）、Rail Route（调度）、Mini Metro（简洁规划）、F1 Manager（赛前定策略、赛中关键介入）、城市与地铁（宏观出行需求模型、草案机制，仅参考思路，不复制代码，其许可禁止商用）

## 核心玩法循环

铁路提高沿线地价，地产收入再投入铁路，这是整个游戏的发动机。

&#91;embedded content: 核心循环 · 6 步，调度作用于乘客\]

规划决定调度难度（单线运能封顶），调度决定乘客满意度和客流，客流决定地价和收入，三层由此连成一体。

## 世界与地图

地图是架空的，世界对齐格子（像 TheoTown 与 A列車），建筑、分区、铁路都按格子放置，铁路允许斜向。真实城市地图以后可作为特别关卡加入，数据格式从一开始就按「能导入真实地图」设计。

**地块大小**：建筑按需要占用多格。

| 类型 | 典型占地（格） |
| --- | --- |
| 独栋住宅、小店 | 1×1 |
| 公寓、办公楼 | 2×2 |
| 车站（按站台长度，6 节编组） | 6×2 |
| 商场 | 4×2 |
| 体育场 | 3×3 |
| 公园 | 4×3 |

**地块合并**：地价上涨后，开发商会收购相邻小地块合并成大地块建公寓（地上げ）。玩家建大型设施也要先凑齐整块地。

**自然地理与玩法**

- **山**：隧道很贵、盘山线绕远；普通铁路坡度有现实上限（约 25‰）
- **河流**：修桥按长度计费；河边地块有洪水风险，暴雨时铁桥限速或停运
- **森林**：开发前需砍伐；保留森林提升周边住宅地价
- **公园**：不赚钱，但提升周边地价和满意度
- **农田**：郊外便宜土地，是「先买地」的主要目标，城市扩张时逐步转为住宅

## 铁路系统

铁路部分必须真实，但例行公事自动化，只把有取舍的决定交给玩家。规划做到「轨道层面」：玩家画线时默认生成复线，再按需加设施，每种设施都花钱、都影响调度。

| 设施 | 作用 | 取舍 |
| --- | --- | --- |
| 单线区间 | 便宜（山区、过江） | 对向列车只能在车站会车，运能封顶 |
| 待避线 | 快车越行慢车，才能开快慢车 | 增加车站造价和占地 |
| 折返线 | 区间车在中途站掉头 | 造价 |
| 渡线 / 道岔 | 故障时绕行，支线接入 | 平面交叉会产生进路冲突 |
| 站台数量 | 换乘站、终点站排车不堵 | 造价和占地 |
| 平交 vs 立交汇合 | 支线汇入主线 | 平交便宜但冲突多 |

**人员**：司机、车站员工、调度员、维修人员。司机有培训期，开新线要提前招人；人手不足会减班。

## 车辆、车辆基地与车站

初期使用固定车型目录，编组节数可在车型允许范围内调整；玩家自主设计车型留到后期。车型名称和制造商一律架空。

**车型属性**

- **编组**：每辆车长、可编组范围（如 2～8 节）、动车与拖车比例（影响加速和造价）、能否分割连结（如 4+6 节）
- **载客**：每辆定员、座椅布局（纵向长椅载客多，横向座椅舒适）、车门数（门越多停站越短）
- **性能**：最高速度、起动加速度、减速度、爬坡能力
- **经济**：每辆价格、每公里维修成本、能耗（再生制动省电）、设计寿命、残值
- **舒适度**：空调有无、噪音、无障碍
- **外观**：车体材质（钢制需定期涂装，不锈钢省维护）、公司涂装可自定义

**示例车型目录**（游戏化近似）

| 车型 | 登场 | 车长 | 车门 | 定员/辆 | 最高速度 | 起动加速度 | 特点 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 木造电车 | 1920 | 15m | 2 | 90 | 65 km/h | 1.8 km/h/s | 便宜，易损，无空调 |
| 钢制通勤车 | 1955 | 18m | 3 | 125 | 95 km/h | 2.5 km/h/s | 需定期涂装 |
| 不锈钢通勤车 | 1975 | 20m | 4 | 140 | 110 km/h | 3.0 km/h/s | 有空调，维护省 |
| 节能变频车 | 1995 | 20m | 4 | 145 | 120 km/h | 3.3 km/h/s | 再生制动，能耗低 |
| 特急车 | 1960 起 | 20m | 2 | 64 座 | 120 km/h | 2.2 km/h/s | 收特急费，载客少 |

**拥挤率**按日本标准：100% 为定员，150% 能摊开报纸，200% 身体互相挤着，250% 以上无法动弹；满意度与方式选择都参考它。

**检修周期**（近似）：列车检查每几天、月检查 3 个月内、重要部检查约 4 年或 60 万公里、全般检查约 8 年；大修期间整列停用数周，需要备用车。

**相关系统**

- **电化与变电所**：变电所容量限制同时运行的列车数；非电化支线可用柴油车（便宜、慢、油费高）
- **轨距**：1067mm 或 1435mm，影响速度与将来直通
- **订购交货期**：新车交货需数月
- **中古车**：旧车可卖给地方铁路，也可买二手车
- **更新改造**：翻新延长寿命、加装空调，比新车便宜

**车辆基地**：由可分别扩建的设施组成，需要大片平地，宜提前买地。

| 设施 | 作用 | 不足时 |
| --- | --- | --- |
| 留置线 | 夜间停放，每条一列，长度须匹配编组 | 只能停车站侧线过夜，有数量限制 |
| 检修库 | 日常检查、月检查 | 检修排队，可用列车减少 |
| 工场 | 重要部、全般检查 | 外包，费用高、周期长 |
| 洗车设备 | 车辆清洁 | 满意度下降 |
| 出入库线 | 连接正线 | 早高峰出库与正线冲突，造成晚点 |

位置设在线路两端最常见，线路中间再设一处可从两个方向同时出车。

**车站升级**

- **形式**：一面一线 → 相对式 → 岛式 → 两面四线待避站 → 终点站、换乘枢纽
- **站台延长**：增加编组的前提，沿线每站都要做
- **增加股道**：待避线、折返线
- **站房**：无人站 → 有人站 → 车站大楼（站内商铺与租金收入）
- **检票**：人工 → 自动检票机 → IC 卡，按年代解锁，减少人员
- **无障碍**：电梯、扶梯，老龄化后需求上升
- **站台门**：减少事故，但要求停靠车型车门位置统一
- **跨线桥 / 地下通道**、**站前广场**、**高架化 / 地下化**

**车站容量**：站台面积与检票口能力决定可承受客流；超过时上下车变慢、停站延长、引发晚点。改造期间部分站台停用、列车限速。

**信号升级**（如自动闭塞 → ATC）缩短最小间隔，不修新线也能提高运能。

## 调度系统

调度分三层，像 F1 Manager 一样「赛前定策略、赛中关键介入」，玩家不需要铁路专业知识。

1. **第一层：安全永远自动**（玩家不碰）
   - 区间（闭塞）同一时刻只属于一列车；列车进入前必须锁定
   - 进路原子预约：单线区间与对面车站的股道一次性一起锁定，否则一个都不锁，对向列车不可能同时开进单线
   - 尾部离开后才释放区间；列车按制动曲线行驶，永远能在已锁定进路的终点前停下
   - **防死锁**：限制每一段（会车站到终点站之间等）同时容纳的列车数，放进去会塞满就让列车在前一站等
2. **第二层：运营方针由玩家定**：各时段发车间隔、运行模式（各站停 / 快慢车 / 区间车）、编组，提供预设方案一键套用
3. **第三层：突发事件介入**：故障、散场客流、晚点扩大时弹出提醒并放慢时间，给出写清效果和代价的选项（折返运转、加开临时列车、快车改各站停等）

自动调度「及格但不完美」，手动介入能做得更好；投资运行指令所、招聘调度员可提高自动水平。平时时间快进，出事时自动放慢或暂停。

**原型验证（8.4 km、6 站线路，8 小时模拟，零碰撞）**

| 列车数 | 复线 每小时班次 | 单线 每小时班次 | 单线 每列每小时等信号 |
| --- | --- | --- | --- |
| 4 | 10 | 10 | 4.6 分 |
| 6 | 15 | 12 | 10.8 分 |
| 9 | 25 | 12 | 25.6 分 |

- 单线约在每小时 12 班封顶，再加车只会排队，周转从 23 分钟拉长到 45 分钟：规划取舍成立
- 单线配 10 列以上出现死锁（会车站到终点之间塞满形成环形等待），所以防死锁必须写进第一层
- 8 小时模拟在电脑上不到 3 秒，时间快进可行

## 列车种别

玩家为每条线定义列车种别：名称、种别色、停车站、是否收费、运行时段都可设定；游戏提供日本私铁常见的预设，名称可改（JR 风格的快速、新快速也可用）。MVP 只有普通，其余种别属于路线图第 1 阶段。

**预设种别**

| 种别 | 停车 | 收费 | 典型用途 |
| --- | --- | --- | --- |
| 普通（各停） | 全部车站 | 无 | 小站居民、夜间 |
| 准急 | 郊外段各站停，市区段跳站 | 无 | 郊外通勤 |
| 急行 | 主要车站 | 无 | 中距离通勤 |
| 快速急行 | 更少的主要车站 | 无 | 远郊通勤 |
| 特急 | 枢纽站 | 无或少量 | 长距离、终点间 |
| 有料特急 | 极少数车站 | 特急费、座位指定 | 观光、远距离 |
| 通勤座席列车 | 少数车站 | 附加费 | 高峰时段有座通勤 |

**运行机制**

- **停车模式**：每个种别选择停靠的车站；停车站之间不减速通过
- **待避**：快车追上慢车的车站必须有待避线（两面四线），第二层自动安排普通在待避站让行；没有待避站就无法开行快慢车组合
- **站台长度**：短站台的小站只能停短编组的普通
- **时段**：例如急行只在高峰开行，夜间全部改为普通
- **分割连结**：支线方向的列车在分岔站拆开或连结（需支持分割的车型）
- **种别色**：在调度指令视图、车站发车牌、列车侧面显示

**和乘客、城市的联动**

- 乘客在站台选择先上普通还是等快车：快车更快但更挤，普通慢但有座
- 快车停靠站的地价和商业更旺，跳过的车站周边吸引力下降
- 被跳过的车站居民会投诉，甚至发起「停车请愿」；增加停车站又会拖慢快车，形成真实的取舍
- 有料特急和通勤座席列车是重要的附加收入

## 运营节奏与外部世界

这些内容都不进 MVP，按路线图分阶段加入；MVP 只带上后台暂停和开局创建公司（公司名、代表色）。

**运营节奏**（路线图第 1 阶段）

- **保线与夜间作业窗口**：轨道随通过的列车重量磨损，状态变差要限速；保线只能在末班车与首班车之间进行，运营时间越长越难安排
- **列车运行图**：横轴时间、纵轴车站、每列车一条斜线的「斜线图」，作为第二层的进阶工具，快慢车待避一目了然
- **末班车、首班车与回送**：夜间列车停在哪里决定次日从哪里发车；无乘客的回送列车也占用线路

**城市生活**（路线图第 2 阶段）

- **季节与节庆客流**：赏樱、新年参拜、烟花大会、盂兰盆返乡等特定日子出现大客流，需加开临时列车；学校放假时通学客流消失
- **公司身份**：标志、涂装自定义
- **公司评价**：准点率、事故、拥挤度累积成口碑，影响卖地价格和涨价审批

**外部世界**（路线图第 4 阶段）

- **并行竞争线路**：地图上有一条背景中的国铁线，玩家用速度、票价、班次与它在同一走廊抢客
- **相互直通运转**：与地铁或其他公司直通，乘客免换乘；受轨距、信号、车型约束
- **补助与废线**：人口减少后郊外支线亏损，可申请地方补助、改为上下分离，或走废线程序
- **劳资事件**：涨薪谈判、罢工停运，作为 1970 年代等时代事件
- **推送通知**：可选开启，提醒台风、大修完成等

## 城市与沿线开发

土地哪里都能买，价格取决于交通；「先买地还是先修线」两种顺序都可行，代价不同，这就是私铁玩法的核心。

**地价**：郊外无铁路最便宜 → 规划公布后上涨 → 车站开通后大幅上涨 → 开发成熟后最高。

**规划公开机制**：线路草案默认保密，这段时间买地最划算；开工前必须公布（申请许可），公布后周边地价上涨。

**持有成本**：未开发土地需缴固定资产税，防止无限囤地。

**分区**：玩家只在自己的土地上指定住宅 / 商业 / 工业，建筑自动长出、升级、老化或衰败。离车站太远的开发收益低，开发自然集中在站周边。

**自然发展**（无 NPC 时提供压力）：市民在城市边缘和道路沿线自发建房，被开发的土地无法再买或很贵；地价整体随时间上涨。

**城市事件**（按现实规律，非纯随机）

- 居民请愿设站，愿意分担建设费（请愿站）
- 郊外大型购物中心开业 → 站前商店街衰退成シャッター街
- 新城居民老龄化，通勤减少、学校关闭
- 工厂迁走、大学搬迁，客流结构突变

**地标建筑**：铁路公司自建（终点站百货店、棒球场、游乐园、剧场、温泉度假村，带来大客流和比赛日、演出日事件）；城市原有或自然出现（神社寺院、城址公园、市政厅、大学、电视塔）。地标手工建模，数量可控。

**双向客流**：郊外终点建大学、游乐园，让早高峰的反方向空车也坐满，同样车队收入更高。

**故事模式（以后）**：在自然发展之上叠加 NPC 地产商、竞争铁路、政府审批与剧情关卡。

## 乘客需求模型

采用交通规划的四阶段模型（简化版），宏观算需求、微观算上车，兼顾真实和手机性能。

1. **出行产生**：住宅地块按人口产生出行，分通勤、通学、购物私事、娱乐观光；比例随人口结构变化（新城年轻家庭多早高峰爆满，老龄化后白天出行增加）
2. **出行分布**：目的地按吸引力（岗位、商业面积）与综合出行时间分配；交通越方便，人们愿意去的范围越大
3. **方式选择**：步行、自行车、市营公交、开车、铁路比较综合成本：步行到站 + 平均等车（发车间隔一半）+ 乘车 + 换乘 + 票价折算 + 拥挤 + 可靠性
4. **路径分配**：乘铁路者选最快路线，得出各区间各时段的客流与拥挤率

**日本特色**

- 公司报销通勤费：通勤乘客对票价不敏感，购物乘客敏感；通学定期有折扣
- 汽车普及（1960–70 年代）会让铁路流失乘客
- 新线客流需几年才成熟（习惯养成）

**时段与方向**：早高峰、平峰、晚高峰、夜间，工作日与周末；早上往市中心、晚上往回，方向性直接驱动调度。

**两层计算**

- 宏观层：按区域汇总，在 Web Worker 中每月或线网变化时重算
- 微观层：换算为每站每分钟到达人数与去向；列车按容量上车，挤不上的继续等（积み残し），调度失误立刻反映在站台
- 画面上的小人只是视觉，不参与计算

**接驳巴士**：车站上一键开设，选择连接区域，自动沿道路生成路线，扩大车站覆盖范围；有车辆和司机成本，可随时撤销。完整公交经营留作以后的扩展。市营公交作为背景出行方式存在，玩家不管理。

**给玩家看**：各站上下车人数、区间拥挤率、站台滞留、出行热力图、乘客抱怨（太挤、晚点、太贵）。

## 道路与踏切

道路主要由城市修，玩家只在自己的地上修路；铁路与道路的冲突会自然出现。

- **城市自动修**：生活道路、干线道路；国道和高速公路作为背景
- **玩家修**：开发地块内的小区道路；站前广场（巴士、出租车停靠，提升车站覆盖与周边商业）
- **出资请求**：玩家可出钱让城市优先修某条路
- 道路车流来自方式选择中「开车」的部分，拥堵反过来影响人们改乘铁路

**铁路与道路交叉的选择**

| 方式 | 造价 | 影响 |
| --- | --- | --- |
| 踏切 | 最便宜 | 车次越多道路越堵，有事故风险 |
| 道路跨线桥 / 地下通道 | 中等 | 铁路不受影响 |
| 铁路高架 / 地下化 | 最贵 | 彻底消除交叉，高架下可开发 |

早期年代可随意设踏切，现代日本原则上不允许新设踏切，新线须立体交叉。

**踏切系统**

- 遮断时间随车次增加；高峰每小时关闭 40 分钟以上为「開かずの踏切」
- 后果：周边拥堵、居民投诉、附近地价下降、救护车被挡等事件
- 事故：汽车困在踏切、行人强行通过；无栏杆无警报的简易踏切事故率更高，可花钱升级；事故导致停运，触发第三层调度与赔偿

**连续立体交差事业**：踏切过多时城市发起请求，把一整段铁路改成高架。大部分由政府和城市出资，铁路公司负担一部分；工期数年，期间走临时线路、限速运行，完工后道路畅通、高架下可开发商铺。

画面上踏切栏杆起落、警报灯闪烁，排队汽车只在镜头附近显示，计算用宏观流量。

## 经济与开局设置

自由模式没有阶段目标，完全自由；经济是「铁路 → 地价 → 地产收入 → 更多铁路」的私铁循环。

**收入**：票款、定期票、卖地、租金、商业设施与地标收入。

**支出**：建设（轨道、车站、设施、桥隧）、车辆购置、人工、检修、能源、固定资产税、利息。

**融资**：银行贷款、发行公司债；资金不足时选择。

**票价**：按距离计费；涨价需申请审批（参考日本上限认可制），涨价会流失乘客、引发舆论。

**优惠方案**：通勤定期、通学定期、换乘优惠、沿线商业联名。定期票收入稳定但单价低。

**故障与事故的处理**：晚点一般不赔钱，安排替代交通（振替輸送）、开具晚点证明、口碑下降；特急晚点 2 小时以上退特急费；人身事故有赔偿与保险。

**开局设置**（自由模式）

| 设置 | 选项 |
| --- | --- |
| 开局年份 | 1920、1955、1975、1990、2010、现在 |
| 初始资金 | 少量、普通、充足、无限 |
| 破产 | 开启 / 关闭 |
| 灾害 | 开启 / 关闭 / 只有天气不出事故 |

选无限资金即纯沙盒；有限资金即经营挑战。

## 时代、天气与灾害

开局年份由玩家选择，游戏需要一张时代年表；战争时期（1937–1945）不做，1920 年开局的游戏平稳推进到战后，不描写战争。

**时代年表的内容**

- **车型与技术**：木造电车 → 钢制通勤车 → 不锈钢车 → 节能车；信号从人工闭塞到自动闭塞、ATS、ATC
- **建筑风格**：昭和、平成、现代
- **物价指数**：建设费、票价、工资随年代变化
- **经济周期**：高度成长期、石油危机、泡沫经济、泡沫破灭、人口减少，作为城市发展的大背景
- **法规**：例如现代原则上不允许新设踏切

**天气与灾害**（按现实运行规则）

- 大风超过阈值限速或停运；可投资防风墙
- 大雨累计雨量达标停运；河边洪水风险
- 台风来临前计划停运
- 大雪道岔冻结；可投资道岔融雪装置
- 地震全线紧急停车检查
- 酷暑钢轨膨胀限速

玩家的决策点：提前计划停运还是冒险运行，以及防灾投资。

**天气表现**：整体色调 + 少量粒子（雨丝、雪花、云层），成本低、氛围足。

## 画面风格

采用低多边形 3D、类似 TheoTown 的斜 45° 俯视（正交相机），可旋转缩放；建筑全部由代码按规则生成，城市演化不需要美术素材。

**建筑生成**：由四个参数决定，按参数选部件（底座、楼层、屋顶、阳台、招牌、遮阳棚、空调外机）拼出建筑。

- **用途**：住宅、商业、工业
- **经济水平**：由地价与居民收入决定
- **年代风格**：昭和（瓦屋根、木造、砂浆外墙）、平成（瓷砖外墙、方正公寓）、现代（玻璃幕墙、塔楼）
- **随机种子**：同类建筑每栋略有不同

**按经济水平的例子**

| 用途 | 低 | 中 | 高 |
| --- | --- | --- | --- |
| 住宅 | 木造公寓、老旧团地 | 独栋、中层公寓 | 带庭院的大宅、塔楼公寓 |
| 商业 | 商店街小铺面 | 杂居大楼 | 办公楼、车站大楼、百货店 |
| 工业 | 町工厂 | 仓库、物流中心 | 大型工厂 |

**老化与重建**：外墙变旧褪色；地价上涨时拆除重建为更高级样式；街区衰退时拉下卷帘门。看街景就知道城市状况。

**昼夜灯光**：窗户随机亮灯（比例 = 人口活动）、路灯与地面光圈、站台照明、招牌、体育场照明塔（亮灯 = 今晚有比赛）、列车车窗和前后车灯、星空；深夜大部分熄灯，末班车后车站熄灯。全部用发光贴图和半透明光晕，不用实时光源。

**调度指令视图**：模仿日本运行指令所的大屏幕，深色底、彩色线条示意图，区间按空闲 / 预约 / 占用着色，列车号标在旁边；竖屏纵向、横屏横向排列。与 3D 城市视图一键切换。

**预览已验证**：等距像素画与低多边形 3D 对比后选定后者；18 种建筑（住宅、商业各 3 种经济水平 × 3 个年代）、自然地形、夜景灯光已有可交互原型。

**原创素材**：车辆外观、车站发车旋律、公司标志全部原创，参考年代特征但不模仿真实的旋律、车型外观和品牌。

## 手机操作与界面

竖屏横屏都支持，做成「一套界面，两种排列」：竖屏适合单手看状态、处理突发、调票价；横屏适合双手铺线和大面积规划。

- **竖屏**：顶部资金 / 日期 / 速度，中间地图，面板从底部弹出（上拉展开），主要按钮放在拇指区
- **横屏**：左侧工具栏，中间地图，右侧可收起的面板
- **地图永远是主角**：一次只显示一个面板，点空白处关闭；提示用短暂 toast，不用常驻卡片
- **旋转不丢状态**：草案、镜头中心、选中对象都保留
- **安全区**：避开刘海、灵动岛、底部手势条；按钮至少 44px
- **小屏测试**：iPhone SE 级别的小屏也不能互相遮挡（避免重蹈《城市与地铁》的问题）

**手势**

| 手势 | 无工具时 | 铺轨工具中 |
| --- | --- | --- |
| 单指拖动 | 移动地图 | 画线 |
| 双指拖动 | 移动地图 | 移动地图 |
| 双指捏合 | 缩放 | 缩放 |
| 双指旋转 | 旋转视角（可吸附四个方向） | 同左 |
| 点击 | 选择 | 落点 |
| 长按 | 查看详情 | 查看详情 |

**铺线流程**：轨道自动吸附格子和车站 → 画完先成为草案（实时显示造价、半径不足、冲突与一键修正）→ 确认后动工；支持撤销。

**后台与通知**：切到后台时默认自动暂停并存档，不在离线期间推进；可选开启推送通知（台风接近、大修完成等）。

**色盲友好**：种别色、区间状态色不只靠颜色区分，同时配文字、图案或线型。

## 技术架构与性能

技术栈为 TypeScript + three.js + Vite 的 Web 应用；以后可用 Tauri 或 Electron 打包桌面版上 Steam。选 Web 的理由：纯文本代码便于 AI 协作开发、一个网址即可在手机上试玩。

**架构**

- **模拟与渲染分离**：模拟核心是纯逻辑模块，可在 Node 中无头测试（原型已验证此做法）
- **固定步长模拟**：方便快进、暂停、存档、回放调试
- **Web Worker**：乘客需求、路径计算等重计算放后台，主线程只负责渲染与交互
- **数据驱动**：建筑成本、增长率、需求公式等参数放配置文件，不写死在代码里；附带调试面板实时调参
- **存档**：状态集中、可序列化，从第一天就设计；本地 IndexedDB

**性能约束**（针对《城市与地铁》手机发烫的教训）

- 同类部件合批 / 实例化绘制（InstancedMesh）
- 远处建筑用简化模型；窗户用纹理而非几何体
- 不做实时阴影；灯光用发光贴图与光晕
- 限制 30fps，画面不变时不重绘；提供省电模式
- 装饰性的行人、汽车只在镜头附近显示，可关闭
- 地图数据按需加载

**测试**：模拟核心的长时间无头测试（不相撞、不死锁、区间不泄漏）作为每次改动的门槛；在实机 iPhone 上测帧率和发热。

## MVP

MVP 只验证一件事：核心循环（买地 → 修线建站 → 分区 → 城市生长 → 乘客坐车 → 收支 → 扩张）在手机上好不好玩。

**包含**

- 一张固定的架空小地图：河流、山丘、一个小镇起点
- 固定开局年份（建议 1960 年前后），时间流逝，暂不做跨时代解锁
- 铺轨（复线为主，可改单线）、建站、一个车辆基地、1～2 种固定车型（编组节数可调整）、种别只有普通、按时段设定发车间隔
- 调度第一层（自动安全 + 防死锁）
- 买地、住宅 / 商业 / 工业分区、城市自动生长、地价随交通变化、按经济水平生成建筑
- 简化四阶段乘客模型（分时段，步行 / 开车 / 铁路），按距离计费
- 开局资金设置（含无限），收入为票款和卖地，支出为建设和运营
- 竖横屏、手势、铺线草案与撤销、车站 / 列车 / 线路信息面板、昼夜光照
- 本地存档；切到后台自动暂停；开局创建公司（公司名、代表色）

**不包含**：人员、检修周期、故障、第三层介入、赔偿、城市事件、踏切问题、地标、接驳巴士、天气灾害、多开局年份、故事模式、声音、多语言。

**开发顺序**（每一步都能在手机上跑起来）

1. 地形、镜头、手势、竖横屏
2. 铺轨工具 + 列车运行 + 闭塞安全
3. 买地、分区、建筑生长
4. 乘客需求、票价、资金
5. 存档与界面打磨

**验收标准**

- [ ] 玩 30 分钟，能修出一条线，看着沿线城市长起来，资金有涨有跌
- [ ] 在 iPhone 上连续玩 20 分钟稳定 30fps、不明显发烫
- [ ] 竖横屏切换不丢状态，面板不遮挡地图
- [ ] 模拟核心无头测试：不相撞、不死锁、区间不泄漏

## 后续路线图与待定事项

MVP 之后按以下顺序扩展，每加一层都先确认好玩再加下一层。

1. **运营真实化**：人员雇佣与培训、多级检修、故障、第二层运营方针完整版、列车种别（准急、急行、特急等）与待避、车站升级、保线与夜间作业窗口、列车运行图、末班首班与回送、第三层事件介入、赔偿与振替輸送
2. **城市生活**：居民请愿、商圈兴衰、老龄化、踏切与连续立体交差、地标建筑、接驳巴士、季节节庆客流、公司评价与标志涂装
3. **自然与时代**：天气灾害、多个开局年份与时代年表、车型和信号技术演进
4. **扩展**：故事模式（NPC 地产商、竞争铁路）、真实城市特别关卡、完整巴士经营、玩家自主设计车型、并行竞争线路、相互直通运转、补助与废线、劳资事件、推送通知、2.5D 之外的视觉增强

- [ ] 地图：每局随机生成，还是精心设计几张固定地图
